# UX 1.5 四步提前收尾设计

## 目标与边界

保留一期六站数据结构，但把用户承诺改成“必填4步，其余可选”。站1至站4继续承载地点、日期、乘客和预算；站4完成后即可使用场景预设进入既有提交前确认链路。站5飞行偏好、站6提醒方式和站3可行性参数默认折叠，用户展开后仍按一期规则把 `monitor_mode` 派生为 `precise`。

本次只改表现层和表现层元数据。字段名、订阅 schema、`build_subscription`、`normalize_subscription`、默认规则、判断、金额、采集和通知正文均不变。

## 单一真值

`form_structure.py` 继续是表单结构的单一真值，并新增三类纯元数据：

- 站点深度：站1至站4为 `required`，站5至站6为 `optional`，可选站默认折叠。
- 可选段摘要：可行性参数、飞行偏好和提醒方式均由 Python 函数生成当前值摘要。
- 编辑展开状态：仅编辑存量 `precise` 订阅时检查分段字段；某段存在非默认值才展开并高亮该段。

模板将这些值输出为 `data-station-depth`、`data-default-collapsed`、`data-optional-section` 和 `data-edit-expanded`。JavaScript 只负责切换已有控件、滚动、刷新摘要和调用既有确认链路，不保存独立业务状态。

## 交互流程

1. 顶部显示“必填4步 · 其余可选”。站1至站4标记“必经”，站5至站6标记“可选”。
2. 站4底部显示主按钮“✓ 完成创建(使用下方预设)”。按钮调用现有默认预览、约束回读和确认卡，不直接绕过校验提交。
3. 场景预设芯片移动到站4主按钮下方，仍由 `/defaults_preview` 和 `defaults_applied` 生成，点击仍只同步底层 input。
4. “想细调时间/航司/提醒？展开可选设置”打开站5并滚动到该处；站5和站6也可分别展开或收起。
5. 移动端未展开可选设置时以站4为必填流程终点；展开后才进入站5、站6。
6. 站3的动身时间与交通冗余原位包进“可行性参数（可选，已按场景预设）”，展开即进入 `precise`，字段归属和提交名不变。

## 兼容与失败处理

- 折叠只改变可见性，不删除或重命名控件；默认值继续由现有服务端规范化补齐。
- 提前收尾按钮与走完可选设置最终都调用同一份 `build_subscription`，一期五场景规范化 JSON 必须逐字段相等。
- 编辑旧订阅时，非默认值必须可见；默认段保持折叠。折叠状态不写入订阅。
- 地点候选、`price_hint`、提交前确认、邮件约束摘要和错误回显沿用一期链路。

## 验证

- 一期五场景夹具在提前收尾路径和完整路径下均逐字段相等。
- Python 单测覆盖站点深度、摘要和编辑展开规则；Flask 路由测试覆盖必要 `data-*` 属性和按钮文案。
- before/after 快照除表现层新增字段外不变；上海-大阪邮件复放不变。
- 双收集器全绿，API 台账与观测库哈希不变。
