# UX 3.2 原生分层设计

## 目标与边界

完整设置页保留六个静态主节，仅用浏览器原生 `<details>` 收纳两组低频参数。折叠不引入自定义 JavaScript 状态，不改变表单字段、订阅 schema、规范化结果或业务判定。

## 概念审计

| 次级组 | 概念 | 规范控件范围 | 归属依据 |
| --- | --- | --- | --- |
| 商务出行 | `same_day_round_trip` | 当天往返 | 决定同日商务执行模型 |
| 商务出行 | `meeting_window` | 会议开始、结束、缓冲 | 仅会议行程使用 |
| 商务出行 | `meeting_location` | 会议地点 | 仅会议到会计算使用 |
| 商务出行 | `meeting_importance` | 会议重要程度 | 驱动商务冗余档位 |
| 商务出行 | `same_day_execution` | 交通方式、车程、冗余 | 仅当天往返会议窗口使用 |
| 商务出行 | `invoice` | 发票与舱位限制 | 企业报销场景使用 |
| 可行性参数 | `set_off_times` | 去返动身时间 | 判断能否赶上航班 |
| 可行性参数 | `transport_estimates` | 出发侧交通估算 | 通用可行性输入 |
| 可行性参数 | `transport_margin` | 交通冗余模式 | 通用可行性输入 |
| 可行性参数 | `reserve_overrides` | 机场与会议缓冲覆盖 | 通用可行性高级输入 |

`cabin` 概念继续留在“飞行偏好”。舱位适用于旅游、个人、团队和商务等所有场景，并直接派生通用 `cabin_classes`；它不依赖会议或发票，因此不属于商务专属组。发票概念中的 `invoice_cabin_limit` 仍随发票设置归入商务组，两者语义不同。

## 渲染规则

- 新建完整设置时，两组默认闭合。
- 编辑存量订阅时，组内任一规范控件偏离服务端默认值，该组渲染 `open`。
- 组内字段仍在 DOM 中，`name` 保持全页恰好一次，渲染完整性契约不变。
- 左侧目录增加“商务出行”和“可行性参数”锚点。
- 开合只由 `<summary>` 的浏览器原生行为完成；生产模板不得设置或切换 `open`。

## 验证

- 单元测试覆盖字段归属、默认闭合、编辑自动展开、舱位归属和唯一性。
- Edge headless smoke 真实点击 `<summary>` 开合，检查闭合内容可被浏览器内核查找，并复放编辑态自动展开。
- 八场景规范化、编辑幂等、邮件复放与 API 台账均不得变化。
