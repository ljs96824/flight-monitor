# P6 预测层设计

## 目标与边界

P6 在现有 P4 `tcurve_v1` 与 P5 依据信封之上增加可解释的价格预测与航班规律描述。预测是市场层证据，不是购买指令；所有输出禁止使用“建议购买”“建议等待”等行动性话术。

本任务保持以下边界：

- `observations.sqlite3` 始终以 SQLite `mode=ro` 打开，运行前后文件 SHA256 必须一致。
- 不触发真实航班 API，不修改采集、金额、排序、推荐或触发判定。
- 不引入 sklearn、prophet 等新依赖，只使用标准库与项目现有依赖。
- 测试数据库和其他磁盘副作用一律使用临时目录。
- `obs_store v2` 的 `departure_time` 字段扩展登记为独立待办，不并入 P6。

## 方案选择

采用“围绕已验证资产增量建设”的方案：

- `forecast.py` 复用 `tcurve.py` 的城市折叠、跨源 `global_min` 日格和 degraded 判定。
- `patterns.py` 复用 P5 的只读观测查询，不复制另一套航线或来源口径。
- 不重构 P4/P5，也不在报告脚本内另写一套 SQL 统计。

## 市场日格与数据口径

预测基底与 T 曲线完全一致：

1. 航线键使用城市级有向键，机场对细分作为可选参数。
2. 每个 `(航线, depart_date, observed_day)` 日格取各源有效报价的全局最低价。
3. 价格口径固定为“单人单程 CNY 含税、乘客系数之前”。
4. 实际来源集合不完整的 degraded 日格默认剔除。
5. 所有统计只描述面板已经覆盖的 `T=days_to_departure`，覆盖外和中间缺失 T 均不插值、不外推。

## 分解预测模型

### shape(T)

对每个 `depart_date` 的可用日格价格序列除以该序列自身中位数，得到归一化轨迹。随后按精确 T 池化，输出：

- `n`
- 中位数
- P10、P25、P75、P90
- 参与观测窗口与来源集合

shape 点即使样本较少也可进入报告，但必须携带 n；最终是否允许进入推送由走前回测技能门控制。

### level(d)

对指定出发日 `d`，计算每个已观测日格的 `price / shape(T)`，以中位数作为 level。输出观测格数、窗口及可靠性：

- `n >= MIN_OBS_FOR_LEVEL`（默认4）：可靠。
- `n < MIN_OBS_FOR_LEVEL`：标记“level不可靠”，不得进入推送。

### 预测与区间

`price_hat(d, T) = level(d) * shape(T)`。

区间随 shape 分位缩放：

- 内层：P25–P75。
- 外层：P10–P90。

未来7天逐日计算目标 T；若目标 T 不在覆盖范围或没有精确 shape 点，该日明确标记“无可用 shape”，不插值。

## 走前回测与技能门

回测按观测日逐日增长：对每个截止日 D，仅使用 `observed_day <= D` 的日格拟合；预测 D+k（k=1、3、7）的实际日格。任何 D+1 及之后数据进入拟合都视为泄漏并使测试失败。

三种模型在共同可评估案例上比较：

1. 分解模型。
2. 朴素持平：预测值等于 D 当日该出发日价格。
3. 静态 T 曲线：仅用截止 D 可见原始价格按目标 T 计算中位数。

每个 k 输出：案例数、MAE、MAPE、相对朴素基线胜率、相对静态 T 曲线胜率。回测门使用累计全量重放案例，禁止滑动窗口化。

技能门为双条件 AND：

- k=3 有效案例数 `>= MIN_BACKTEST_CASES`（默认5）。
- k=3 MAPE 相对朴素基线改善 `>= SKILL_GATE_IMPROVEMENT`（默认10%）。

门未过时模型仍进入独立报告，但不得进入通知 payload。

## 假日事实标签

新增 `holidays.py`：

- 维护中国大陆、日本 2026 年及已知 2027 年法定节假日静态表。
- 中国已公告年份记录国务院年度公告的官方放假区间；未公告年份仅记录法定日期，并在 note 标注“调休安排未公布”。
- `HOLIDAY_SHOULDER_DAYS` 默认1，可配置。
- 标签必须包含国别、节名和相对位置，例如“中国·国庆(当天)”或“日本·秋分(节前1日)”。
- 假日仅解释 level，例如“该出发日 level=1.4×，处于中国·国庆窗口”，不进入价格修正、排序或判定。

机场国别只从 `AIRPORTS` 主字典读取。现有54个机场代码全部补齐 `country`，`validate_airports()` 将其纳入必填校验，禁止半填充字段。

`method_registry.py` 注册 `holiday_calendar_v1`；假日数据使用冻结摘要守卫，增删改日期必须显式更新测试与版本。

## 航班规律 patterns_v1

所有规律均为事实描述，携带 n、窗口和口径。

### 航班组合出现率

按近 N 个不同观测日计算组合在架天数占比。标签与原始数字始终并排：

- 常驻：出现率 >=80%。
- 偶发：出现率 <=20%。
- 中间区间：间歇出现。

展示格式如“常驻(93%·n=15)”，禁止裸标签。

### 航司价格位置

按市场承运航司统计单人单程中位价，以及该航司提供当日最低价的天数占比。文案明确“市场承运口径”，与 LCC 的执飞航司口径区别开。

### 班期稳定性

按 `(flight_combo, depart_date)` 去重后统计星期几分布，避免同一出发日被多轮观测膨胀。

起飞时段固定输出：“面板未存起飞时刻(obs_store v1)，待schema扩展后自动点亮”。不得显示空横线或进行猜测。

### 直飞与中转供给比

优先读取 `stops`；字段缺失时才按组合段数推断。报告披露实际使用的依据；若发生结构推断，标注“基于组合结构”。

所有规律使用 `MIN_PATTERN_N`（默认5）门控；不足时显示“样本不足(n=X)”。

## 依据信封与方法版本

`method_registry.py` 新增：

- `forecast: forecast_v1`
- `patterns: patterns_v1`
- `holiday_calendar: holiday_calendar_v1`

预测信封不携带用户约束指纹。其 bucket 固定声明：

`市场最低参考价·单人单程·与用户筛选无关`

信封包含标准字段及预测扩展：方法版本、样本 n、窗口、实际贡献源、degraded 剔除数、回测成绩、数据截止日和 computed_at。

## 报告与通知

### 只读报告

`scripts/forecast_report.py --route 上海-大阪` 输出：

- shape 逐 T 表。
- 各出发日 level、可靠性与假日标签。
- k=1/3/7 对双基线成绩单及技能门状态。
- 各出发日未来7天预测中位和双层区间。
- patterns_v1 四类规律与起飞时段缺口说明。

无数据或不可预测时输出清晰原因，不生成空表。

### 通知硬闸

“价格预测参考(实验)”仅在以下三条件同时满足时渲染：

1. 技能门通过。
2. 当前出发日 level 可靠。
3. 目标 T 在覆盖范围且有精确 shape 点。

门未过时仅打印：

`[预测] 技能门未过(MAPE=X% vs 基线=Y%) 跳过渲染`

并且不向 payload 添加 forecast 字段，从而保证门未过场景输出零漂移。

小节内容只陈述预测中位、P25–P75、P10–P90、回测证据与历史变化事实。必须包含层级声明：

“预测对象为该航线市场最低参考价，你的筛选后方案价可能持续高于此曲线。”

当两类价格均可得时，附带示例数值，例如“当前筛选后方案价 CNY10,431 vs 市场参考下限 CNY7,470”。

## 测试与验收

使用 TDD，所有 fixture 数据库位于临时目录：

- shape 归一、分位数和 level 精确值。
- level 可靠性边界。
- 覆盖外及中间缺 T 禁止预测。
- 回测截止日泄漏防线。
- k=1/3/7 双基线、累计案例和技能门两侧。
- 中日假日、肩部标签、54机场 country 完备与冻结守卫。
- patterns 四指标、80%/20% 边界、数字与标签并排。
- 起飞时段缺口完整说明。
- 推送三条件门及市场层声明。
- method registry 冻结守卫与 forecast 信封。
- 面板数据库运行前后 SHA256 一致。

最终验证包括双收集器、本地离线报告、上海—大阪复放、快照差异、配额台账哈希及 GitHub Actions Ubuntu/Windows 四格。
