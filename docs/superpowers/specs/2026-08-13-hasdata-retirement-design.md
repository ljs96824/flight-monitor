# HasData 退役设计

## 目标

自 2026-08-14 起，国际航线停止调用 HasData，仅使用聚合数据（Juhe）搜索，并保留 Duffel 作为行李/退改规则参考。历史观测、历史推送和 HasData 解析代码不删除。

## 边界

- 仅调整 `international` 源策略；`greater_china` 按本任务明确范围保持现状。
- 不修改价格、筛选、排序、触发和双源一致度算法。
- 不删除 `hasdata_source.py`、历史观测或相关 mock 测试。
- 固定篮子配置本身不改；采集计划按当前源策略自动过滤国际 HasData 请求。
- 篮子旧允许列表中的退役源视为已满足，不再触发“缺少配置源”；队列、强制新鲜、哨兵、台账和轮档语义不变。

## 配置模型

`source_profiles.py` 的国际配置保留 HasData 退役元数据：旧角色、权重、退役日和原因。当前 `sources` 只包含 Juhe 与 Duffel。

期望列表源按观测日派生：

- 观测日早于 2026-08-14：`hasdata + juhe`。
- 观测日在 2026-08-14 及以后：`juhe`。
- 未提供观测日：使用当前策略，即 `juhe`。

这样新 Juhe 单源日格不退化，退役前日格的历史判定不被当前配置反向改写。

## 一次性声明

通知 payload 增量附加 `source_retirement`。上一推送仍含 HasData，或订阅尚无上一推送时，显示一次退役声明；成功持久化后，下一轮快照仅含当前源，声明不再显示。

历史 payload 没有该字段，继续走原渲染分支，保证历史复放不变。计划退役源也从故障退化候选中排除，避免出现“本轮Google数据源不可用”措辞。

## 验证

- 当前国际策略及采集计划均不含 HasData。
- 首轮声明出现，次轮消失。
- 退役前/后的日格退化判定分别保持旧/新期望集合。
- 双源一致度仍按滑动窗口自然衰减。
- 历史 payload 复放不变，API 台账不变。
