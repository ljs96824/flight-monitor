# 通知渠道回归修复实施计划

**目标：** 恢复表单第六站的邮件、PushPlus、两者三态渠道，修复默认值、显隐、编辑回填与服务端缺省兜底，并补齐通知配置契约。

**边界：** 仅修改表单结构、通知配置规范化、只读体检脚本和离线测试；不触碰采集、分析、金额、排序或真实通知发送。

## 步骤

1. 新增失败测试，锁定三态控件、`both` 默认、邮箱显隐协议、编辑回填和缺省规范化。
2. 提取通知配置单一真值，兼容历史 `page_only`，新建表单只展示三态。
3. 让 `web_form.py`、`form_structure.py`、`main.py` 共用同一默认与校验规则，并输出 `[通知配置]` 诊断。
4. 新增只读残缺订阅扫描脚本，不修改 `subscriptions.json`。
5. 扩展兼容基线为七场景，新增 `email-only` 与 `both`，保留原五场景规范化结果逐字段不变。
6. 生成 after 快照并对比，运行定向测试、双收集器全量测试，核对台账与观测库哈希不变。
7. 仅在全部离线验证通过后创建独立提交；不推送、不触发真实 API 或邮件。
