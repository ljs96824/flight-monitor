# 单源退化披露与证据保全实施计划

## 目标

在不改变航班筛选、价格、采集计划和排序算法的前提下，修复成功空结果被缓存洗白、源缺席被解释为售罄，以及轮次日志无法追溯的问题。

## 实施顺序

1. 用离线快照锁定改前 payload，并记录配额台账和观测库哈希。
2. 先补失败测试：空结果缓存、结果侧退化、追踪措辞、轮档、篮子哨兵。
3. 失败/空结果只保留在本轮结果池，不写 15 分钟持久缓存；Juhe 自身缓存同样拒绝空结果。
4. 从 source_stats 的有效方案数构建退化上下文，首轮完整披露、连续轮紧凑披露；追踪器消费同一上下文。
5. 为订阅轮、集合轮和篮子轮增加按日追加轮档，并把 listing 源非成功/空响应完整脱敏落档。
6. 主循环轮末检查当日篮子台账，超过阈值且未运行时只通知一次。
7. 重跑快照、定向测试和双收集器，确认台账/观测库哈希不变后独立提交。

## 不变量

- 不调用真实外部 API。
- 正常双源 payload 与邮件不新增退化字段或文案。
- 不改变价格、预算、筛选、排序和采集请求集合。
- 所有磁盘副作用测试使用临时目录。
